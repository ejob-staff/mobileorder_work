# DB設計
この資料は、モバイルオーダーアプリのDB設計として<br>
DBテーブル概要と初期データを整理したものです。

## 1. DBテーブル概要
`app_user`:

ユーザー情報を管理する<br>
ユーザー名、パスワード、表示名、権限、利用状態を持つ<br>

`user_management_code`:

ユーザー管理番号を管理する<br>
管理番号、使用済みかどうか、使用ユーザー名、作成日時、使用日時を持つ<br>

`product`:

商品情報を管理する<br>
商品名、説明、カテゴリ、値段、在庫数、公開状態、表示用アクセントを持つ

`mobile_order`:

注文情報を管理する<br>
注文番号、ユーザー名、注文日時、受け取り日時、合計金額、ステータス、キャンセル理由、受取完了日時を持つ

`order_item`:

注文に含まれる商品情報を管理する<br>
商品ID、商品名、注文時の値段、数量を持つ

`product_review`:

商品評価を管理する<br>
注文番号、商品ID、商品名、ユーザー名、評価、感想、登録日時を持つ

一般ユーザー用: USER-CODE-英数字12桁<br>
管理者用: ADMIN-CODE-英数字12桁

プレミアム

`初期注文`:

いちごタピオカミルクティの注文数を多めに登録する<br>
注文分析、人気順、評価表示が確認しやすいようにサンプル注文を登録する

`初期評価`:

いちごタピオカミルクティは高評価が多くなるように登録する<br>
商品選択画面の評価表示、管理者の注文評価確認画面、注文分析画面で確認できる

`注意`:

DataInitializerは対象テーブルにデータが存在しない場合に初期データを登録する<br>
既にDBにデータが入っている場合は新しく追加した初期データは自動追加されない場合がある<br>
初期データを入れ直したい場合はDBデータをリセットしてからアプリケーションを起動する
